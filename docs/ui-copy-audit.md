## 一、统一对象与操作

| 对象／操作 | 建议中文 | 建议英文 | 必须保留的区别 |
| --- | --- | --- | --- |
| Telegram 私聊、群组、频道的统称 | 会话；首次出现时说明“私聊、群组或频道” | Chat；首次说明“private chats, groups, and channels” | `channel` 的独立类型标签仍译为“频道 / Channel”；不把所有对象称为频道。英文导航可用 `Chats & channels`，内部字段优先用 `Chat`，避免 `Destination`。 |
| RSS Feed，共享抓取实体 | 订阅源 | Feed | 同一订阅源可推送给多个会话。不能因打开某一行的订阅设置，就暗示对共享订阅源的修改只影响这一行。 |
| 一个会话与一个订阅源之间的关系 | 订阅 | Subscription | 同一订阅源订到两个会话计两条订阅；订阅源数按来源去重。必要时才在解释中写“订阅关系”。 |
| 列表的会话筛选 | 按会话筛选 | Filter by chat | 只改变列表显示，不添加接收对象，不改变推送。 |
| 新建订阅的接收对象 | 选择接收会话 | Choose a receiving chat | 创建该会话与订阅源的订阅。 |
| 共享订阅源的多个接收对象 | 管理接收会话／选择接收会话 | Manage receiving chats / Choose receiving chats | 这是改变推送接收者，不是列表筛选，也不是给 Agent 授权。 |
| Agent 令牌的对象范围 | 选择允许管理的会话 | Choose chats this token can access | 仅授权所选会话的订阅操作，具体能力取决于只读／读写权限。 |
| Bot 用户的状态与权限 | Bot 用户角色 | Bot user role | 不等于 Telegram 群管理员、部署配置中的 `MANAGER`、网页登录账号或 API 令牌权限。 |
| 部署配置中的 MANAGER | 机器人管理者 | Bot manager | 作为部署中的最终权限根，与普通“Bot 管理员”分开。 |
| 网页登录身份 | 管理台管理员 | Console administrator | 不把“会话与频道”的用户设为管理员当作创建网页登录身份。 |
| 外部程序访问管理 API 的凭据 | API 访问令牌 | API access token | 创建／撤销的是令牌；不要在同一流程轮用“连接授权”“连接密钥”“完整密钥”“Agent 授权”。 |
| 让一条订阅停止／重新推送 | 暂停订阅／恢复订阅 | Pause subscription / Resume subscription | 保留订阅关系和个性设置；不等于封禁会话或恢复备份。 |
| 移除一份会话订阅 | 取消订阅 | Unsubscribe | 不影响其他会话对相同订阅源的订阅。 |
| 阻止会话使用机器人 | 封禁会话／解除封禁 | Block chat / Unblock chat | 封禁会暂停该会话的订阅；解除封禁不会自动恢复订阅。 |
| 减少列表干扰 | 隐藏已封禁会话／显示已封禁会话 | Hide blocked chats / Show blocked chats | 显示筛选不改变角色、订阅或数据；不与暂停、取消订阅混用。 |
| Telegram 退出动作 | 让机器人退出群组／频道 | Remove the bot from the group / channel | 动作主体是机器人；与网页“退出登录”区分。 |
| 运行配置删除网页覆盖 | 使用部署配置（重启后生效） | Use deployment configuration after restart | 可能回退到环境变量或应用默认值，不保证是出厂默认值。 |
| 备份恢复的三个阶段 | 检查备份 → 安排重启后恢复 → 重启时恢复 | Validate backup → Schedule restore on restart → Restore during restart | 检查通过或任务保存均不等于数据已经恢复。 |

上述词表是修正目标，不要求将代码中的 `target`、`Feed`、`Sub` 或稳定 API 字段重命名。数据模型、权限和原 Bot 行为保持原意。
