# 会话归档与封禁会话的显示

归档用于整理管理台，不删除 Telegram 会话、不让机器人退出、不改变角色或封禁状态，也不暂停或取消订阅。仍启用的订阅继续推送。需要停止推送时，应暂停订阅或封禁会话。

## 操作

1. 在“会话与频道”勾选一个或多个会话，选择归档；确认弹窗会说明保留的数据与推送行为。
2. 未归档列表和接收会话选择器不再显示这些会话。切换“已归档”可找回，勾选后取消归档。
3. 查看已归档范围时，默认包含已封禁会话；恢复归档不会解除封禁。
4. 机器人管理者不可归档；全选只选择当前页可操作的会话，切换列表条件会清空选择。

## 订阅与接收会话

- 默认“全部订阅”及对应 OPML 导出排除已封禁会话的订阅，过滤在计数与分页之前执行。
- 若明确从已封禁会话进入“管理订阅”，仍可检查其保留的暂停订阅；封禁期间不能恢复订阅。
- 接收会话选择器不提供已封禁或已归档会话；修改一个订阅源的接收会话时，只调整可选会话的关系。
- 已封禁或已归档会话原有的订阅保持不变，包含它们的订阅源继续采用原来的共享抓取机制。
- 归档的非封禁会话订阅仍出现在全部订阅中，因为它们可能仍在正常推送。

## 接口与兼容

`GET /api/targets` 支持 `archive=visible|archived|all`，默认 `visible`；独立的 `visibility` 参数仍控制封禁和活跃状态。结果新增 `archived` 布尔值。

`POST /api/targets/archive` 接收 `{"ids":["-1001"],"archived":true}`；设为 false 恢复。每次 1–100 项，先校验所有会话再原子写入归档标记。仅网页登录管理员可操作，Agent 令牌不能归档。

归档信息存于独立管理表，不修改上游数据库结构。备份包含归档信息；恢复不包含归档信息的旧备份时，清除当前归档标记，避免把新标记错误地应用到旧数据。

## 验证重点

- 批量归档、刷新后找回、恢复；检查订阅、默认设置、角色和封禁状态均未改变。
- 管理者、未知 ID、越权令牌及非法输入被拒绝；一组请求包含不可操作会话时，不部分归档。
- 全部订阅不包含封禁会话，明确按该会话查看仍可检查历史订阅。
- 接收会话替换不会删除被隐藏的订阅，直接提交封禁或归档 ID 会得到明确原因。
- 中英文、手机宽度、全选与筛选清空、键盘操作、备份往返及旧备份恢复。
