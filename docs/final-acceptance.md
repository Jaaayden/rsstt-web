# 最终整合版验收

用户已将流程调整为先合并全部功能与验收修正，再集中测试整合版。合并代码不代表部署到线上。原版实例保持运行；测试入口使用真实快照的本地工作副本。

## 测试边界

- 网页修改只作用于本地副本，不会影响原始快照或线上实例。
- 离线预览不抓取真实 RSS、不发送 Telegram 消息、不发送真实外部通知。通知测试会明确显示为模拟。
- 预览保留用户已修改的登录密码；网页改密后，最初提供的密码不再自动有效。
- 原版未保存的历史推送计数不能补回；新版统计从开始采集时计算，未记录区间不能当作零。
- 当前网页自动恢复适用于 POSIX 上的文件 SQLite；不支持的平台应明确禁用相关操作，导出仍可使用。

## 第一轮：优先复验用户提出的问题

| 项目 | 操作 | 通过标准 |
| --- | --- | --- |
| 会话选择器 | 分别打开订阅筛选、添加订阅、修改接收会话、API 令牌授权范围；用长名称搜索，切换手机宽度及深浅色 | 控件尺寸正常，名称和类型不挤压；单选/多选正确；文字准确说明正在筛选、选择接收会话或授权范围；键盘可选、关闭后焦点回到入口 |
| 已封禁会话的显示 | 打开会话列表，切换未封禁、已封禁、全部、活跃、不活跃；组合搜索、类型筛选并刷新/翻页 | 默认隐藏已封禁；切换可找回；总数与分页匹配；隐藏不删除数据。活跃口径为未封禁且存在已启用订阅，其订阅源也已启用 |
| 改密与错误提示 | 输入错误当前密码；随后输入正确当前密码和新密码；重新登录 | 前者明确告知当前密码错误且未修改，不误报会话过期；成功后旧会话失效、旧密码不能登录、新密码可登录 |
| 封禁后的订阅操作 | 封禁一个有订阅的会话，尝试单条及批量恢复，再解除封禁 | 明确告知因封禁而不能恢复，并说明解除封禁步骤；订阅仍暂停；解封不自动恢复 |
| 全站用语 | 在中英文间切换，检查按钮、字段、说明、确认弹窗、空列表、错误提示 | 区分订阅源与会话订阅、接收会话与授权范围、Bot 角色与网页登录账号、已保存与已生效；不存在误导性的“更新中”“刷新后重试”等兜底说明 |

## 第二轮：核心管理流程

| 项目 | 操作 | 通过标准 |
| --- | --- | --- |
| 按会话查看订阅 | 从一个会话进入其订阅列表，搜索并刷新，再清除筛选 | 只显示对应会话的订阅，URL/刷新/前进后退保留正确筛选；清除后显示全部 |
| 多会话推送关系 | 选现有订阅源，追加一个接收会话，再用替换模式移除其中一个 | 追加不移除旧关系；替换仅移除未选关系；仍保留的订阅自定义设置不变；同源不生成重复 Feed |
| 单条设置与默认值 | 修改会话默认推送选项，再让某条订阅继承或单独覆盖 | 保存/重开可回读；继承与独立覆盖语义清楚，不影响其他订阅的独立设置 |
| 导出 OPML | 按会话筛选后导出全部筛选结果，再选几条导出 | 筛选导出不限当前页；所选导出只含所选订阅源；同源去重。OPML 不包含接收会话、推送选项、账号和密钥 |
| 独立 User-Agent | 为一个订阅源保存测试 UA，再清空 | 保存后可回读，清空恢复全局值；说明该源所有接收会话共用此请求配置，其他源不受影响；真实 HTTP 请求不在离线测试范围 |
| 角色与权限边界 | 调整普通用户角色，查看受保护管理者和频道角色选项 | 管理者不可降级/封禁；群组/频道不可设为用户管理员；Bot 用户管理员不会成为网页登录管理员 |
| 配置与生效时机 | 修改一个合法非敏感运行配置，刷新，再移除网页覆盖 | 已保存值、当前进程使用值及待重启状态清楚；删除覆盖表示下次启动使用部署配置；敏感值不回显；保存不会自动重启 |
| 仪表盘 | 检查已记录/活跃会话、订阅总数/订阅源数、小时/日期切换 | 定义与数字对应；一源多会话计数有解释；未知历史不伪造成零；UTC 日汇总与本地小时显示区分清楚 |

## 第三轮：通知、备份与 Agent

| 项目 | 操作 | 通过标准 |
| --- | --- | --- |
| 通知配置 | 保存通知总开关、抓取失败阈值、最短间隔及新会话通知；使用模拟测试并查看记录 | 保存后可回读；渠道凭据不回显；测试明确标为模拟。管理台异常标记阈值与外部通知阈值不混淆 |
| 备份导出与检查 | 导出默认备份，选择文件检查内容与兼容性，再查看恢复选项 | 默认备份不包含凭据；检查不会覆盖数据；默认保留现有账号和令牌。只有备份实际包含相应凭据时，才能选择覆盖它们 |
| 恢复安排与取消 | 安排重启后恢复，确认待恢复状态，再取消 | 安排成功不等于已经恢复；取消保留当前数据。需要验收实际恢复时，由主会话配合重启本地预览并核对结果 |
| API 访问令牌 | 创建仅允许一个会话的只读令牌，保存密钥，刷新后检查列表，再撤销 | 完整令牌只显示一次；名称、范围、期限准确；API 只能读取授权会话，写入和管理操作被拒绝，撤销后请求失败 |

## 自动化与实发验证的区别

Bot 原命令兼容、长 `/list` 分页、API 越权/事务保护、备份重启恢复及 Linux 限额压力已有自动化验证，最终结果以对应提交的测试和 CI 为准。网页点击成功不能代替这些不变量检查。

真实 Telegram 的收发、频道权限、媒体和外部通知送达仍需独立测试机器人或后续明确授权的部署环境验证；不要启动第二个连接线上 Bot Token/session 的预览进程。

新问题在主会话提交：页面或操作、实际结果、预期结果；主会话维护反馈清单和修正记录。已有通过项无需为了按 PR 编号重新完整测试，优先关注本轮修正和此前未测功能。
