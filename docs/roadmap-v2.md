# RSStT Web 第二轮开发与验收

## 目标与边界

基于当前可工作的 Web 管理台，覆盖用户提出的 17 项改进。保留官方 Telegram 命令、原数据库和共享抓取机制；不操作线上原版实例。开发按独立 Git 分支和工作目录并行，主会话统一协调，用户只在主会话反馈。PR 未经用户逐个验收不得合并或部署。

当前基础版先独立保存为 PR 0。各功能 PR 以基础版为起点，避免把尚未合并的基础改动重复列入每个功能 diff。合并基础版后再调整后续 PR 的目标分支。

## 共同实现约定

- 继续使用 Python、aiohttp、Telethon、Tortoise 与轻量原生网页；新增依赖须有实际必要性，生产无需 Node.js。
- Web 关闭时保留官方行为。扩展功能采用独立模块、独立管理数据表与明确的生命周期钩子，不重写抓取和推送核心。
- 所有写入接口必须经过权限验证。Agent 通过公开 API 操作，权限与令牌明确绑定，不读取 Bot Token 或 Telegram session。
- UA 按 RSS 来源配置；同一来源向多个目的地发送时共用抓取，不按接收会话重复抓取。
- 活跃使用量依据启用的订阅与可使用账号计算；已知会话总数与活跃会话数分别标注。未核验的频道/群组类型不得猜测。
- 现有累计统计不能从原版历史倒推。小时/日趋势要有明确保留时间和有界存储。
- 环境变量映射区分可即时生效、重启生效和部署基础设置。不能用“保存成功”冒充已经应用；进程安全与连接凭据不写日志或 Git。
- 不改变 FeedLantern；可以只读参考其通知、Agent API/CLI、权限和交互设计。
- 真实数据只位于被 Git 忽略的 `.preview/` 中。测试使用独立副本，禁止复制生产认证文件、联网发消息或让两个进程共享机器人数据库/session。
- 每个 PR 包含对应测试、接口说明、适用限制与可复现的验收步骤；共享文件改动保持局部并提前报告契约。
- 普通体验问题记入反馈清单，留待最后统一修复。数据丢失、越权、认证绕过与 Bot 行为破坏必须在进入可合并状态前解决。
