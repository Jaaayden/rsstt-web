## F001：目的地选择器布局

- 代码证据：`app.css` 的通用 input 样式应用了 `width: 100%`、最小高度和内边距，但仅 checkbox 覆盖尺寸，radio 没有对应覆盖。`targetPicker()` 的单选模式使用 radio，且名称直接作为 flex 容器的文本节点，缺少独立的可伸缩文字区域。此组合与用户截图中的控件放大、文字挤压一致。
- 修正范围：单选/多选控件使用固定尺寸且不伸缩；图标、名称、类型分别布局；长名称可读，类型标签不被挤成逐字换行；保留整行点击、键盘选择与焦点状态。检查筛选、添加订阅和其他复用该选择器的入口。
- 回归要求：桌面与窄屏、中英文/长名称、浅色与深色下验证控件及文本实际边界；同时验证选择、搜索和已选状态。不能只用点击成功代替布局验证。
- 用户截图作为本地私有验收证据保存，不提交到仓库。

## F002：会话显示范围

- 默认显示“未封禁”，隐藏已封禁会话；提供“未封禁 / 活跃 / 不活跃 / 已封禁 / 全部”筛选，不另建重复管理页面。
- “活跃”指未封禁且至少有一条启用订阅；“不活跃”指未封禁且没有启用订阅。封禁与不活跃分开表达，不因没有启用订阅就将会话视为封禁。
- 隐藏仅改变列表显示，不删除会话、订阅或历史信息，也不改变 Bot 权限。用户可通过“已封禁”或“全部”找到会话并继续管理。
- 状态筛选与搜索、类型筛选组合；在服务端分页前应用，列表总数与分页一致；筛选进入 URL，使刷新、前进和后退保持一致。
- 回归要求：覆盖已封禁但保留订阅、未封禁且全暂停、活跃会话、空结果及跨页场景；默认列表隐藏已封禁，“已封禁”与“全部”能找回，数据保持不变。
