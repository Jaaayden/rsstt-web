# RSStT Web 管理台

这是基于 [RSS-to-Telegram-Bot](https://github.com/Rongronggg9/RSS-to-Telegram-Bot) 的 Web 二开版本。保留上游的 RSS 抓取、内容格式化、推送与 Telegram 命令，增加网页管理台、管理 API 和独立管理数据。管理台与增强版机器人运行在同一进程中，不能直接接管另一个未修改的原版进程。

快速部署见 [README](../README.zh.md)，以下说明页面行为、配置、安全边界与离线测试方式。

## 页面与功能

| 页面       | 能力                                                                                                                                                   |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 仪表盘     | 已知及活跃会话、订阅关系、独立来源、需要检查数量、新发现文章与成功推送累计值；24 小时、7 天、30 天趋势，以及最近管理操作。                             |
| 会话与频道 | 按名称、用户名、ID 搜索，按类型与显示范围筛选；角色、Bot 语言、订阅上限、默认推送选项、服务控制、状态同步、会话记录、OPML 导入导出。                   |
| 全部订阅   | 分页、名称／网址／会话／状态筛选，添加、取消、暂停、恢复和批量操作；自定义标题、标签、格式与更新间隔；编辑同源接收会话、单源 User-Agent 和 OPML 导出。 |
| 运行日志   | 按来源、会话、类别与严重程度查看抓取、推送、通知和系统诊断；查看失败原因、HTTP 状态、耗时、重试安排及恢复记录。                                        |
| 设置       | 更新与订阅默认值、运行配置、通知、备份与恢复、API 访问令牌、实例信息、账户安全。                                                                       |

网页支持简体中文与英文，以及浅色、深色和系统外观。Bot 回复语言在每个会话中单独配置，与网页语言独立。

### 会话列表和服务控制

会话列表来自 RSStT 已有用户记录和后续接入事件，不是 Telegram 全部对话的枚举。没有可靠名称时显示 ID；未确认的频道／群组类型显示“未知”，不根据封禁或普通用户状态猜测类型。

- 默认显示未封禁会话，并排除机器人已退出、被移除或停用的会话。
- 显示范围包括“未封禁／活跃／不活跃／已封禁／全部”。“已封禁”和“全部”可查看封禁记录；**这些筛选不会找回已退出会话**。API 提供 `include_departed=true`，当前网页没有对应入口。
- 活跃状态依据可用会话及启用的订阅、来源计算，不表示用户在线，也不表示最近已经成功推送。
- “停止服务并封禁”会保留会话记录、暂停订阅并阻止后续使用。解除封禁后，订阅不会自动恢复。
- 群组和频道可选择“让机器人退出”。在线实例会调用现有 Telegram 客户端，确认后保存退出状态并暂停订阅。私聊应通过封禁停止服务。
- 管理者受保护，不能通过网页降级或封禁。普通用户的 Bot 管理员角色不授予网页登录账号或环境 `MANAGER` 的专属权限。

在线实例监听机器人自身加入、退出、被移除，以及首次私聊事件，启动后进行一次分批核验。普通成员的进出不等于机器人的成员状态变化；网络失败和普通权限错误不能证明机器人已经退出。

“已加入，发送权限待确认”只确认成员身份；“上次核验可发送”还要求验证相应发送权限。状态更新时间不是用户在线时间，也不能保证权限此后没有变化。详见[会话服务控制、状态与操作记录](chat-service-control.md)。

### 订阅和来源

同一个 RSS 来源被多个会话订阅时共享抓取，推送偏好保存在各自订阅关系中。可以追加或替换接收会话，无需在 Bot 中反复取消、重新订阅。

默认全部订阅、相应 OPML 导出及接收会话选择器会排除封禁、退出会话。明确按某个会话查看时仍可检查保留的订阅；替换其他接收会话时保留隐藏的已有关系，避免误删未展示的数据。来源 User-Agent 对该来源共享的抓取生效，不按接收会话重复抓取。

“需要检查”的失败阈值默认是 3，只统计启用订阅的来源连续抓取失败。成功抓取后上游将连续失败次数归零。这个页面阈值不替代上游的退避或自动停用策略，也不自动修改通知模块的独立阈值。

### 运行日志

从异常订阅旁的“抓取日志”进入该来源的诊断，也可在“运行日志”集中筛选。每条记录显示时间、结果和已取得的诊断信息，例如 HTTP 403、连接超时、RSS 解析失败、Telegram 发送权限不足或通知渠道请求失败。详情包含可用的 HTTP 状态、异常类型、耗时、连续失败次数、下次重试时间或限流等待时间；没有取得的数据不会推测补齐。

抓取日志按 RSS 来源记录。同一来源被多个会话订阅时共享抓取记录；发送问题按接收会话记录。会话的“操作记录”继续保存用户和管理员做过的设置变更，运行日志用于排查程序执行问题。备份预检／暂存、运行配置保存、会话状态核验及统计记录异常也会留下对应系统记录。

日志从启用本功能后开始保存，**不能从“连续失败 40 次”反推出之前每次失败的原因**。真实快照预览不运行抓取器，因而历史明细为空；新建的示例演示会提供明确属于演示数据的样本。

记录保存在管理数据库中，批量写入有界队列。最多保留 30 天、全实例 5000 条、每个来源 100 条，达到任一上限时清理较旧记录。日志写入失败不阻断 Bot；页面会显示存储异常或本次运行丢弃的记录数。普通成功推送不会逐篇写日志。进程被强制终止可能丢失尚未写入的记录，因此这里是故障诊断历史，不是不可丢失的审计账本。

日志仅网页登录管理员可读，Agent 令牌无此权限。记录不包含普通聊天内容、文章／响应正文、请求头、Cookie 或原始凭据；URL 的认证、路径、查询和片段不会保存到诊断中。原有终端日志仍可用于深入排查进程启动问题。逻辑备份包含经过过滤的运行日志，旧版备份可以继续恢复。

## 接入真实机器人

### Docker Compose

使用本仓库的 [`compose.console.yaml`](../compose.console.yaml)，按 [README](../README.zh.md#使用-docker-compose-快速部署) 创建私有 `.env`，然后构建：

```sh
docker compose -f compose.console.yaml up -d --build
```

该文件从本仓库构建 `rsstt-web:local`，容器内监听 `0.0.0.0:8730`，宿主机仅发布 `127.0.0.1:8730`，并持久化 `./config:/app/config`。上游镜像和 `docker-compose.yml.sample` 不包含本 fork 的网页管理台。

升级现有实例时，先备份并停止原进程，再替换构建；保留原有 Token、Telegram session、数据和必要的代理设置。同一个 session／主库只运行一个机器人进程。

### 从源码开启管理台

管理台使用 Python 3.12／3.13 验证。保留原有 `TOKEN`、`MANAGER`、`API_ID`、`API_HASH` 和代理等实际需要的配置，增加以下环境配置：

```dotenv
WEB_ENABLED=1
WEB_HOST=127.0.0.1
WEB_PORT=8730
WEB_ORIGIN=http://127.0.0.1:8730
WEB_PASSWORD=replace-with-a-private-random-password
```

通过原入口启动：

```sh
.venv/bin/python telegramRSSbot.py -c ./config
```

`WEB_ENABLED` 默认关闭。开启后 API 与机器人共用进程和事件循环，网页修改复用原有订阅业务，并更新调度。生产无需 Node.js、前端构建器或额外前端服务。

### 登录与访问地址

`WEB_PASSWORD` 为 16–512 个字符，只用于首次初始化空的管理台账号；之后密码哈希保存在 `console_admin` 表中。修改环境变量不会覆盖已有账号密码，请通过“设置 → 账户安全”改密。

登录表单只填写管理台密码。成功登录获得 8 小时的 HttpOnly、SameSite=Strict Cookie；HTTPS 地址额外设置 Secure。重启或成功改密会撤销网页登录会话，Agent 令牌则按独立的有效期与撤销状态控制。

网页写入校验同源地址，不开放 CORS。反向代理时将 `WEB_ORIGIN` 改为浏览器实际访问的完整 HTTPS 源站地址，管理台路径保持在 `/`。Docker 容器内的监听地址与宿主机发布地址不同，不能只把容器内的 `WEB_HOST` 改成回环地址。

Docker 镜像构建、离线导入、安装包资源和资源限额检查已有 CI 覆盖；这些结果不能代替真实 Telegram 发送、成员权限、退出操作或实际通知渠道的验收。上线前使用独立测试机器人和测试会话验证相关行为，具体矩阵见 [CI 说明](ci.md)。

## 设置、通知与恢复

### 运行配置

“更新与订阅”管理默认／最短更新间隔、会话订阅上限、上限提示和页面提醒阈值。会话的语言与默认推送选项在会话设置中修改。

“运行配置”只开放已校验的白名单，保存到配置目录中的 `runtime-config.json`。这些值在**重启后**应用；保存不会重启机器人，也不证明远端凭据或网络连接有效。敏感值不回显，输入留空保留原值；“恢复部署默认值”删除网页覆盖，重启后重新使用部署值。

管理者身份、数据库地址、Web 监听地址及进程选项等仍属于部署配置。字段映射与生效时机见[用户角色与运行配置](pr-02-users-settings.md)。

### 通知

“通知”支持 Bark、Telegram、Webhook 和 ntfy，默认关闭。配置并启用渠道后，可按独立阈值接收连续抓取失败、恢复和新会话接入通知；重复通知由去重与冷却时间控制。

新会话包括首次私聊、机器人新加入群组或频道，也覆盖首次命令被拒绝的使用尝试。升级或重启不会将既有记录当作新会话重复通知；普通成员加入群聊不触发机器人接入通知。

离线模式的渠道测试和结果是模拟，不表示真实通知已经发出。密钥不回显，具体流程见[通知说明](pr-05-notifications.md)。

### 备份与恢复

“备份与恢复”支持文件 SQLite 主库和管理库的逻辑 JSON 导出、恢复预检、覆盖范围选择和暂存。恢复任务在正常重启时应用，不会由网页直接覆盖运行中的数据库或触发进程重启。

默认不导出网页登录凭据、Agent 令牌或通知密钥；恢复默认保留目标实例的凭据，覆盖需要显式选择。主机器人 Token、Telegram session、部署环境和网页登录会话永远不进入逻辑包。包内仍可能包含私有 RSS 地址、会话资料和操作记录，应妥善保存。

网页备份上限 32 MiB；自动恢复要求 POSIX 主机和文件 SQLite。PostgreSQL 使用文档中的独立维护流程，Windows 不支持此自动恢复流程。详细的预检、回退和凭据策略见[备份与恢复](pr-06-backups.md)。

## 本地开发与预览

开发验证使用 Python 3.12／3.13；浏览器测试使用 Node.js 22。先创建环境并安装开发依赖：

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
export WEB_PASSWORD="$(.venv/bin/python -c 'import getpass; print(getpass.getpass("Initial console password: "))')"
.venv/bin/python -m src.management.demo
```

打开 `http://127.0.0.1:8730`，用首次启动时输入的私有密码登录。示例数据存储在 `.demo/` 的独立数据库中。RSS 和 Telegram 使用离线替身，网页、API、数据库与订阅业务使用实际实现。`WEB_PORT` 和 `WEB_DEMO_CONFIG` 可指定其他端口及独立数据目录。

**示例演示**中的退出操作会模拟本地状态改变，不向 Telegram 发送请求。**真实数据快照预览**则明确拒绝退出，不应把示例演示的结果当作真实快照或线上退出已经成功。两种预览都只监听本机回环地址，不能作为公开生产服务使用。

开发检查：

```sh
.venv/bin/python -m pytest -q
npm ci
npx playwright install --with-deps chromium
npm run test:e2e
```

### 用线上真实数据做离线测试

`scripts/export_console_snapshot.py` 可通过 SSH 标准输入执行，使用只读连接和 SQLite backup API 将原版 RSStT 数据库复制到内存，再把压缩包输出到本地。它包含已提交到 WAL 的数据，不在服务器保存脚本或备份文件，也不停止或重启机器人。服务器 Python 需要 3.11+。

替换下列端口、账号、主机与路径：

```sh
umask 077
mkdir -p .preview/source
ssh -p PORT USER@HOST 'python3 - --database /path/to/config/db.sqlite3 --session /path/to/config/bot.session' \
  < scripts/export_console_snapshot.py > .preview/snapshot.tar.gz
```

确认 SSH 命令成功退出、下载完成后，再解包并启动预览。首次启动前先按上面的方式设置私有 `WEB_PASSWORD`：

```sh
tar -xzf .preview/snapshot.tar.gz -C .preview/source
.venv/bin/python -m src.management.preview --snapshot .preview/source --config .preview/work --port 8731
```

`--session` 可省略。提供时只读取数据库中已知会话的 ID、缓存名称和用户名，不导出电话号码、access hash、Telegram auth key 或完整 session。快照不包含 `.env` 或机器人 Token。名称可能已过时，当前 Telegram 权限无法离线验证，类型不明确的会话显示“未知”。

预览页面标注“真实数据离线预览”和快照时间。首次启动生成独立工作副本，重启保留本地修改；原始快照保持不变。`.preview/` 已排除在 Git 和 Docker 构建上下文之外，快照仍是私有数据，应保留在本机。

可测试分页、筛选、编辑、暂停／恢复、删除、OPML、授权和本地操作记录。新增 RSS 使用离线替身，不抓取内容或验证 RSS 地址；通知测试也为模拟。快照预览不启动 Telegram 客户端、监控器或调度运行器，并拦截 Python 的 TCP、UDP、DNS 外连。实时同步、登记快照之外的会话和真实退出会话会明确拒绝。

原版没有管理台累计推送和小时历史，快照预览将这些数据标为不可用，不生成示例统计，也不把未知当作零。订阅状态与失败次数来自导出时刻，不代表当前线上状态。

需要重置测试时先停止预览，用新的 `--config` 目录启动同一快照；更新快照时使用新的来源目录和工作目录，不能在同一工作目录上覆盖另一份快照。

## 数据、统计与操作记录

原 RSStT 表结构和 Aerich 迁移流程保持不变。新增的 `config/console.sqlite3` 保存管理凭据哈希、会话缓存、统计、通知配置、操作记录及运行日志；`runtime-config.json` 保存网页运行配置覆盖值。主库可用 SQLite 或 PostgreSQL，管理库为本地单实例 SQLite，需要持久化整个配置目录。

- **新发现文章**：监控器新发现并保存的条目数量。同源共享抓取，不按接收会话重复计算；首次订阅建立的历史条目基线不计入。
- **成功推送**：一篇内容完整发送到一个会话计 1 篇次，发到 3 个会话计 3 篇次；拆成多条 Telegram 消息仍计 1 篇次。空内容、拒绝、丢弃和不完整发送不计成功。
- **累计值**：独立总计长期保留，删除订阅或清理趋势不会重置。无法重建启用统计前的历史值。
- **趋势**：提供 24 小时、7 天、30 天范围。按 UTC 小时和日期聚合，分别保留 31 天、90 天；小时标签显示本地时区，日视图明确使用 UTC 日期。未记录、超出保留期及不完整时间段有独立标记，不按完整零值填充。
- **实例最近操作**：仪表盘保留最近 200 条管理操作记录。
- **会话记录**：在会话设置中查看 Bot、网页、API 操作的时间、发起人、安全的动作名称、处理结果和观察到的设置前后值。每会话最多 100 条、全实例最多 2000 条，单条约 4 KiB，有界快照或内容截断会标注。

会话记录不保存普通聊天正文、原始请求、原始回调数据、密码或完整令牌；已知敏感模式会脱敏。审计普通只读命令时，不会额外读取该会话的全部订阅快照。命令调用完成不证明请求目的已经达成，是否改变设置应看变更记录。旧版本未保存的交互历史无法补回。

统计或审计记录失败会显示降级或不完整状态，机器人继续运行。Telegram 发送和本地统计不构成同一个分布式事务：发送成功后、统计提交前强制终止进程可能少计，远端接受但响应丢失也不能作为已确认成功计入。详见[统计与活跃使用量](pr-04-statistics.md)和[会话记录边界](chat-service-control.md#会话操作记录)。

完整停机备份应保护整个配置目录，并单独备份 PostgreSQL（如使用）；其中可能包含 Telegram session 和部署凭据。在线 SQLite 副本必须使用 backup API，不能只复制主文件而漏掉 WAL。网页逻辑备份的导出范围与完整部署备份不同。

## 管理 API 与外部集成

在“设置 → API 访问令牌”创建 `read` 或 `write` 授权，明确选择允许管理的会话，或显式允许全部会话及今后新增会话。有效期为 1–365 天，完整密钥只显示一次，可随时撤销。

请求头为 `Authorization: Bearer <连接密钥>`，接口前缀 `/api`，需认证的 OpenAPI 契约位于 `/api/openapi.json`。CLI 默认只预览写操作，`--apply` 才实际请求；删除或接收者替换另需 `--confirm-delete`。完整说明见[认证与 Agent 接入](pr-01-auth-agent.md)。

| 方法       | 路径                                                             | 用途                                                                            |
| ---------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| GET        | `/api/session`                                                   | 查询授权身份、权限、会话范围和有效期。                                          |
| GET        | `/api/targets?q=&kind=&visibility=&page=1&size=20`               | 查询授权范围内的已知会话；API 默认 `visibility=all`，不等于网页默认显示未封禁。 |
| GET        | `/api/subscriptions?target=&q=&state=&attention=&page=1&size=20` | 查询订阅，每页最多 100 条。                                                     |
| POST       | `/api/subscriptions`                                             | `{"target":"-100…","urls":["https://example.com/rss"]}`，每次最多 100 个地址。  |
| PATCH      | `/api/subscriptions/{id}`                                        | 更新状态、标题、标签、间隔和推送选项。                                          |
| DELETE     | `/api/subscriptions/{id}`                                        | 取消指定会话中的订阅。                                                          |
| POST       | `/api/subscriptions/batch`                                       | 对最多 100 条订阅执行 `pause`、`resume` 或 `delete`。                           |
| GET        | `/api/subscriptions/opml`                                        | 按筛选或选中的订阅导出 OPML。                                                   |
| GET / PUT  | `/api/feeds/{id}/recipients`                                     | 查询或追加／替换授权范围内的接收会话。                                          |
| GET / POST | `/api/targets/{id}/opml`                                         | 导出／导入某个会话的 OPML，导入上限为 512 KB、100 个地址。                      |
| POST       | `/api/targets/{id}/refresh`                                      | 使用写授权校验允许访问的会话并更新名称；离线快照拒绝实时同步。                  |

会话查询支持 `include_departed=true`，用于显式查询授权范围内的已退出记录，当前网页没有这个开关。`kind`、`visibility` 等参数的可接受值以当前契约为准。Telegram 会话 ID 在 JSON 中使用字符串，集成端应保留完整精度。

写授权只提供订阅相关能力，不授予全局仪表盘、角色／默认设置、运行配置、授权签发、备份或会话交互记录访问权限。新增接口默认不向 Agent 开放。会话历史接口 `GET /api/targets/{id}/activity?page=1&size=20` 只允许网页登录管理员。

跨会话操作在修改前检查完整授权范围。同一会话重复添加同一 RSS 不覆盖已有自定义标题、格式或暂停状态；新增结果按条返回 `created`、`existing` 或 `failed`。接收者替换保留范围外关系及隐藏会话的已有订阅。

`write` 授权允许实例读取提交的 HTTP(S) RSS 地址，包括自建内网源，应按实际部署管理授权范围和网络出口。外部应用可保存实例地址和专用授权，将 RSS 地址提交给此 API；抓取与推送继续由 RSStT 完成，不需要共享数据库。当前没有专用 FeedLantern 适配器、多实例控制或用户自助网页登录。

## 验证范围

自动检查覆盖后端权限与业务、浏览器交互、Bot 命令兼容、数据库迁移、安装包资源和脱离源码目录启动、Docker 构建及离线资源限额工作负载。具体覆盖范围见 [CI 说明](ci.md)，是否通过以对应提交的实际 CI 结果为准；不把旧提交结果或模拟传输视为真实联网验收。

上线前需要在独立测试机器人中验证私聊推送、频道权限、成员加入／退出、通知实发、媒体和长文拆分，以及原有 Telegram session 的兼容。离线演示和真实数据副本可以验证本地网页行为，不能证明这些远端效果已完成。
