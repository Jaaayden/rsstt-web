# 会话服务控制、状态与操作记录

“会话与频道”用于管理已接入机器人的私聊、群组和频道。默认隐藏已封禁以及机器人已退出、被移除或停用的会话；不提供归档功能。类型筛选只有 Telegram 的三种类型；快照中缺失类型的行显示“未知”，不猜测类型。

## 停止或恢复服务

- 在会话设置的“服务控制”中选择“停止服务并封禁”，确认后暂停该会话订阅，并沿用原版权限检查拒绝后续使用。保留封禁信息，避免清理数据库后意外解除封禁。
- 群组和频道还可以选择“让机器人退出”。只有 Telegram 确认操作后才保存退出状态，并暂停订阅；退出后从默认列表和接收会话选择器消失。
- 私聊不能让机器人代替对方删除整段聊天，应使用封禁停止服务。清理记录与控制使用权限是两种不同动作。
- 解除封禁不会自动恢复订阅；机器人重新加入群组或频道，也不会自动恢复已暂停的订阅。
- 管理者受保护，不能通过网页封禁或降级。

## 当前状态的证据

在线版本复用正在运行的 Telethon 客户端，监听机器人自身加入、退出、被移除，以及首次私聊事件。普通群成员的进出不当作机器人的服务关系变化。

启动后在后台进行一次分批核验；不按固定周期全量扫描，不启动第二个 Telegram 客户端。启动核验尚未完成时，页面可能仍展示最后保存的状态。网络失败、普通权限错误不能证明机器人已退出，因此不据此隐藏会话。

“已加入，发送权限待确认”只表示确认了成员身份；“上次核验可发送”还要求读取并确认相应发送权限。“状态更新时间”不是用户在线时间，也不保证 Telegram 权限此后没有变化。订阅的启用数量描述配置状态，不代表最近实际推送成功数。

离线预览不接收线上 Bot 事件，也不发送 Telegram 消息。示例数据演示可以模拟退出并暂停本地订阅；真实数据快照预览会拒绝退出操作，不能用它验证 Telegram 成员关系的变化。

## 新会话通知

在“设置 → 通知”开启通知总开关与“新会话接入时通知我”，保存并启用至少一个通知渠道。记录首次私聊或机器人新加入群组、频道，也覆盖首次命令被拒绝的使用尝试。既有会话在升级或重启时不会当作新会话重复通知；普通成员加入群聊不触发机器人接入通知。

## 会话操作记录

在会话设置中打开“会话记录”，可查看 Bot、网页及 API 操作：时间、发起人、安全的操作名称、处理结果，以及实际观察到的设置前后值。命令处理结束不等于请求目的已达成；是否改变设置以变更记录为准。

- 记录原版命令与按钮操作、订阅变更、权限与推送默认值，以及机器人加入/退出。
- 不保存普通聊天正文、原始请求、原始回调数据、密码或完整令牌；已知敏感模式会脱敏。
- 每个会话最多保留最近 100 条，全实例最多 2000 条；单条内容有大小上限，截断会明确标记。
- 旧版本未记录的历史无法补回。日志从启用本版本后开始，离线副本只能演示本地管理操作。
- 审计记录失败不阻断原 Bot 命令，网页会提示记录存储异常或记录可能不完整。
- 会话记录随备份保存；恢复不包含记录的旧备份时清除当前记录，避免错配旧数据。

接口 `GET /api/targets/{id}/activity?page=1&size=20` 仅允许网页登录管理员；Agent 令牌不能读取用户交互记录。

## 订阅与接收会话

默认全部订阅及对应 OPML 导出排除封禁、退出会话。明确按某个会话查看时仍可检查它保留的暂停订阅。接收会话选择器不提供这些会话；替换接收会话时保留被隐藏的已有订阅，避免未展示的数据被误删。

## 验收顺序

1. 查看三种类型筛选与未知行标签，确认没有归档入口。
2. 对一个测试会话停止服务，确认订阅暂停、默认列表隐藏；从封禁范围找到并解除封禁，确认订阅没有自动恢复。
3. 在独立测试群组或频道让机器人退出，确认 Telegram 成员身份、列表及订阅状态。示例数据演示只模拟本地过程；真实数据快照预览会拒绝退出操作。
4. 修改推送选项后打开会话记录，检查来源、发起人及前后值；在测试机器人内执行设置命令，再核对相应记录。
5. 开启新会话通知，用独立账号首次私聊或把测试机器人加入新群组/频道，检查通知一次送达；关闭开关后重复新增场景不应送达。
6. 测试封禁会话不出现在默认全部订阅及接收候选中；保存其他接收会话时，它的已有订阅仍保留。
