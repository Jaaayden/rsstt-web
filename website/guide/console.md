## 页面如何保持最新

数据不只在网页里变化：在 Telegram 里用命令改了订阅设置，或者定时抓取更新了订阅源，网页都需要跟上。概览、会话、订阅、运行日志和打开的详情面板会自己保持最新，不用刷新整个网页：

- **回到页面时**：切回这个标签页或窗口重新获得焦点时，超过 10 秒没更新的内容立刻重新读取。
- **停在页面上时**：每分钟重新读取一次屏幕上的内容（概览里的趋势图变化很慢，每 5 分钟一次）。标签页在后台、或者超过 15 分钟没有任何操作时不再请求；设置页没有需要自动更新的内容，也不请求。
- **手动刷新**：概览、会话、订阅、运行日志的右上角有“刷新”按钮，旁边写着“更新于 3 分钟前”，点一下立刻重新读取当前页面和打开的详情面板。
- **编辑到一半时**：详情面板里的表单在别处被改动时，你没碰过的项会换成新值，你已经改过的项保留你的修改，所以保存时不会把别处刚改的内容覆盖回旧值。

为什么没有做成 WebSocket 或 SSE 推送：机器人改数据库不经过管理台，管理台要推送就得自己定时去查数据库，和浏览器每分钟查一次没有区别；而推送要处理反向代理的空闲超时、断线重连和登录过期，复杂得多，对单用户的自托管服务不值得。

打开页面也更快了：切到另一个页面时先显示上次读到的内容，同时在后台更新；鼠标移到侧栏的页面上时就提前读取，登录后不久也会静默预读其他页面的第一屏；点开订阅或会话的详情面板时直接用列表里已有的数据，不再等一次请求；暂停和恢复订阅的按钮先显示新状态，服务器拒绝时再还原；各页面首次加载时显示占位的骨架，不再是整页转圈。

## 版本号

登录页和登录后每个页面的侧栏底部（手机上在菜单里）都显示当前的 `RSStT Web x.y.z`，有构建信息时带上短提交号。悬停看完整提交号，点一下复制，反馈问题时直接贴即可。“设置 → 关于这个实例”里有完整信息。登录页只显示版本号，提交号登录后才显示。

## 概览

- **服务中的会话**：有启用订阅的私聊、群组、频道数量。
- **订阅**：启用与暂停的数量、订阅源数量。
- **累计推送**：成功推送的篇次与新文章数（从启用管理台后开始统计）。
- **需要处理**：连续抓取失败次数达到阈值的订阅。
- **推送趋势**：24 小时、7 天按小时，30 天按天；鼠标悬停看具体数字。

## 会话

列出所有使用机器人的会话。点“管理”打开详情面板：

- **概况与权限**：设置角色（管理员 / 用户 / 访客 / 已封禁）。封禁会暂停这个会话的全部订阅并拒绝它之后的命令；群组和频道可以“让机器人退出”。
- **订阅**：这个会话的订阅，可导入 / 导出 OPML。
- **推送默认值**：等同于机器人里的 `/set_default`，对选择“跟随会话默认”的订阅生效。
- **操作记录**：这个会话在机器人里用过的命令、网页上做过的修改。

默认不显示已封禁的会话，用右上角的筛选切换。

私聊用户的名称在对方给机器人发消息时记录；管理台上线前就在用的用户，启动时会从机器人的 Telegram 会话里补全，也可以点“补全名称”。查不到的显示为“用户 123456”。

## 订阅

按标题、网址、会话、状态筛选。搜索和筛选条件会写进地址栏（`#subscriptions?q=关键词`），刷新网页或把链接发给自己时保留；输入时只替换当前地址、不产生浏览历史，停止输入约 0.25 秒后才查询，拼音等输入法组字过程中不查询。勾选后底部的操作条可以批量：暂停、恢复、**立即抓取**（逐个抓取所选的源，有新文章照常推送）、设置检查**间隔**、设置**代理**、**复制地址**、导出或取消订阅。新添加的订阅会在后台立刻检查一次，抓取记录和最近文章马上有内容（已有的文章不会推送）。点击订阅打开详情：勾选后底部的操作条可以批量：暂停、恢复、**批量设置**（见下）、**立即抓取**（逐个抓取所选的源，有新文章照常推送）、设置检查**间隔**、设置**代理**、**复制地址**、导出或取消订阅。新添加的订阅会在后台立刻检查一次，抓取记录和最近文章马上有内容（已有的文章不会推送）。点击订阅打开详情：

- **设置**：自定义标题、hashtag、检查间隔、推送格式（文字与机器人 `/set` 菜单一致）。
- **接收会话**：这个 RSS 源推送到哪些会话。增减会话即可，不用再 `/unsub` 后 `/sub`；同一个源只抓取一次。
- **最近文章**：最近 20 篇文章及其推送到当前会话的结果。
- **抓取**：立即检查更新并推送、测试推送最新一篇；为这个源单独设置**代理**（跟随全局 / 直连 / 使用代理，可先“测试这个设置”）和 User-Agent。
- **日志**：默认显示“抓取记录”——这个源每次抓取的时间、耗时、读到多少篇、新增多少篇；结果相同的连续检查合并成一行（如“共 53 次检查 · 有效 36 条 · 新增 0 条”），有变化才新增一行。另一个标签“事件与推送”显示失败原因、有更新、恢复和推送结果。每个源保留的行数可在“设置 → 订阅规则”里调整（默认 20 行）。

### 批量设置

选中若干订阅，点操作条里的“批量设置”：**单个订阅里能改的每一项，这里都能一次改给所选的全部订阅**——自定义标题、hashtag、检查间隔、订阅状态（暂停 / 恢复）、推送格式的每个选项（消息通知、发送方式、长度上限、链接预览、媒体、文章标题、作者、来源、文章自带的 hashtag、消息风格）、订阅源的 User-Agent 和代理、接收会话（添加 / 移除）。取值和单个设置完全一样，包括“跟随会话默认”。

- 每一项开始都是“保持不变”，**只有勾选的项才会被修改**；没勾选的项在每个订阅上保持各自原来的值。比如只勾选“媒体”并选“禁用”，就是给所选订阅统一关闭图片，其余设置原样保留。
- 标题、hashtag、User-Agent 留空表示清除；检查间隔和代理选“跟随默认 / 跟随全局”表示清除订阅自己的设置。
- User-Agent、代理是订阅源自己的设置：同一个源被多个所选订阅使用时只改一次，没被选中的接收会话也会受影响。添加接收会话会让所选订阅涉及的每个源也推送给这些会话（新增的接收关系使用该会话的推送默认值）；移除接收会话相当于在那些会话里 `/unsub`，会先让你确认。
- 所选订阅里有些保存失败时（比如接收会话已被封禁而无法恢复），其余照常保存，结果里会逐个列出失败的订阅和原因，以及它已经保存的部分。操作条上原有的“间隔”“代理”按钮仍然可用。

## 运行日志

有两个视图：“事件”是抓取失败、推送异常、通知发送和系统事件；“抓取记录”是所有订阅源的每次抓取（可按有新文章、成功、失败筛选）。事件每条都直接写出原因，例如：

- `HTTP 403 · 网站拒绝访问，可能拦截了机器人（可尝试更换 User-Agent）`
- `连接超时，网站响应太慢或无法访问`
- `返回内容不是有效的 RSS/Atom`
- `机器人没有在这个会话发消息的权限，或已被移出/屏蔽`

没有新文章的正常检查不会逐条记录。

## 通知

“设置 → 通知”：

- **通过本机器人发给我**：最省事，机器人直接私聊所有者（需要你先对机器人发过 `/start`）。
- 也支持另一个 Telegram 机器人、Bark、ntfy、Webhook。
- 可以在订阅源连续失败 N 次、恢复正常、有新会话开始使用机器人时通知。通知里写明订阅源名称、链接、失败次数，或者新会话的名字，并附管理台链接。

## 设置里的其他内容

- **订阅规则**：默认 / 最短检查间隔、订阅上限（等同于 `/set_option`）。
- **运行配置**：原本写在部署环境里的配置，网页上可改，显示当前生效值和来源；按类别折叠成组，可搜索设置名、变量名或说明，说明点设置名旁边的 ⓘ 弹出；Telegraph Token 可一键获取。保存后重启生效，可直接点“立即重启”。
- **备份与恢复**：导出备份；上传备份先预检，再暂存到下次重启时恢复。
- **API 访问**：为脚本或 AI Agent 创建令牌，见 [API 与 Agent](./api)。
- **账户与安全**：修改账号和密码、退出所有设备、立即重启机器人。登录页需要账号和密码（首次登录账号是 `admin`，密码是 `WEB_PASSWORD`），浏览器和 iCloud 钥匙串可以直接保存。
