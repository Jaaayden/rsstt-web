# 更新日志

## 1.4.2

- **榜单类订阅源不再隔一阵子重复推送同一篇文章**：RSStT 靠记住已经见过的文章来判断“有没有新文章”，但每个订阅只记住当前这批文章，再加上最近离开的同样多的一批（至少 100 篇）。文章在榜单里进进出出的订阅源（热门榜、精华榜、把多个来源合成一个的订阅），离开一段时间再回来，早就被忘掉了，就会当成新文章再推送一次。现在记忆的长度跟着订阅源的规模走：当前文章数的 30 倍，最少 100，最多 20000。例如一个每次列出 300 篇的订阅会记住最近 9000 篇，大约覆盖十几天的进出。
- 只有真的有文章离开过的订阅才会用到更长的记忆：很少更新的普通订阅记住的数量基本不变。不需要任何设置，也没有数据库迁移。
- 记忆是慢慢长出来的：升级时已经被忘掉的记录找不回来，之后每次发现新文章，才会多留下离开的那些。所以一个进出很频繁的订阅，要过几天到十几天才能达到完整的窗口，这期间重复会一天比一天少。
- 代价：记住 9000 篇大约占 105 KB 的数据库空间，每次发现新文章时多读写这一份；实测处理这些记录大约 0.4 毫秒。只有进出很频繁的订阅会涨到这个量级，其余订阅几乎不变。
- 为了节省空间，记录用的是文章标识的 32 位校验值，所以记得越多，一篇真正的新文章与旧记录“撞车”被漏掉的概率也越大：记住 9000 篇时约为二百万分之一，对每天出现几百篇的订阅源，大约两年漏一篇。

## 1.4.1

- **订阅检查记录不再被拆成一条一条**：不少订阅源（比如论坛的 RSS）有时回复“没有变化”（HTTP 304，使用缓存），有时重新返回一遍全部内容（HTTP 200，没有新文章），两种回复交替出现。之前它们被当成不同的结果，所以记录里总是“一整段合并的检查 + 一条使用缓存的检查”交替出现。现在这两种“没有新文章”的检查只要文章数一致就合并成同一条，显示为“共 N 次检查 · 有效 N 条 · 新增 0 条”。有新文章、失败、手动检查，以及文章数发生变化的检查依然单独成行。
- 升级后第一次启动时，会把已有的检查记录按同样的规则合并一次。只会合并相邻的、相同结果的记录，次数、耗时的最小 / 最大 / 平均值都会累加到合并后的那一条，不会丢失信息。

## 1.4.0

- **订阅的批量设置做完整了**：之前多选订阅后只能暂停、恢复、改检查间隔、改代理，要关闭图片之类的推送格式只能一个订阅一个订阅地改。现在操作条里有“批量设置”：单个订阅里能改的每一项——自定义标题、hashtag、检查间隔、订阅状态、推送格式的全部 10 个选项（含“媒体”，也就是不推送图片）、订阅源的 User-Agent 和代理、接收会话的添加与移除——都能一次改给所选的全部订阅，取值和单个设置完全一致（包括“跟随会话默认”）。每一项开始都是“保持不变”，只有勾选的项才会被修改。部分订阅保存失败时，其余照常保存，结果里逐个列出失败的订阅、原因和已经保存的部分。原有的“间隔”“代理”等按钮不变。
- 批量设置和单个订阅的设置共用同一份选项定义和同一套校验；测试会在两边出现不一致时失败（给单个订阅新增了设置项却没有加到批量里），以后不会再漏项。
- **一眼看到版本号**：登录页和登录后每个页面的侧栏底部都显示 `RSStT Web x.y.z`（有构建信息时带短提交号），悬停看完整提交号，点一下复制。登录页只显示版本号。API：`GET /api/public` 新增 `version`，`GET /api/session` 新增 `version`、`build`。
- API：`POST /api/subscriptions/batch` 新增 `settings` 操作，请求体 `changes` 可包含单个订阅 `PATCH` 支持的全部设置，以及 `user_agent`、`proxy`（仅管理台管理员）、`add_recipients`、`remove_recipients`；请求整体不合法时返回 400 且不修改任何订阅，否则逐个订阅返回结果和已保存的分组（`applied`）。OpenAPI 契约已更新。原有的 `pause`、`resume`、`delete`、`interval` 行为不变。
- **网页控制台更跟手**：量过之后问题不在服务器（接口响应只要几毫秒），而在每次点击都要等好几轮网络往返：切换页面时整页重新读取并显示转圈，打开订阅详情要先请求一次再请求两次，暂停订阅要等服务器回应才变样，首次加载要逐级下载脚本。现在：
  - 切换页面先显示上次读到的内容，后台更新；侧栏鼠标移上去就开始读取，登录后静默预读其他页面的第一屏；
  - 订阅和会话的详情面板直接用列表里已有的数据打开，不用等请求；
  - 暂停 / 恢复订阅立刻显示新状态，服务器拒绝时还原并提示；
  - 首次加载并行读取脚本和登录状态，列表首次加载显示占位骨架而不是整页转圈。

  在模拟 300 毫秒网络往返时：冷启动打开概览 2.5 秒 → 1.4 秒；切回订阅页 0.8 秒 → 0.03 秒；打开订阅详情 0.8 秒 → 0.03 秒；暂停订阅变样 0.33 秒 → 0.02 秒。
- **数据自动保持最新**：在 Telegram 里改了设置，回到网页（标签页重新可见或窗口重新获得焦点）会自动刷新，停在页面上时每分钟刷新一次，后台标签页和长时间没有操作时不再请求；概览、会话、订阅、运行日志右上角新增“刷新”按钮和“更新于……”提示。详情面板里正在编辑的表单遇到别处的改动时，保留你已经改过的项，其余项换成新值。
- **搜索更省**：输入拼音等需要组字的文字时，组字过程中不再查询；搜索条件写进地址栏的行为不变（替换当前地址，不产生历史记录，停止输入后才查询）。
- 修复：同一个页面里重复读取同一份设置、同一个会话的请求现在合并为一次。

## 1.3.2

- **WebP 图片不再显示成贴纸**：有些网站不论文件名都返回 WebP，而图片转换服务 `wsrv.nl` 拒绝转换部分域名的图片，这样的图片会退回为 WebP 文件，在 Telegram 里显示成贴纸，并且和正文分成两条消息。现在 `wsrv.nl` 无法转换时，由 RSStT 自己下载并重新编码为 JPEG 照片发送；以 `.gif` 结尾但实际返回 WebP 的地址同样处理，动态 WebP 只保留第一帧。如果在本地下载或重新编码也失败，则沿用原有的发送方式。

## 1.3.1

- **添加订阅后立刻检查一次**：之前添加订阅时只读取一次来验证地址，读到的内容没有记录，于是刚添加的订阅在“最近文章”和抓取记录里都是空的，要等到下一次定时检查（默认间隔之后）才有内容。现在添加成功后会在后台立刻对新订阅源做一次正式检查：抓取记录里马上有第一行，最近文章里出现订阅源当前的文章。这些已有的文章不会推送（和机器人原本的行为一致），只有之后发布的才推送。多个地址一起添加或导入 OPML 时按顺序逐个检查；订阅源已经在被监控时（别的会话订阅过）不会重复抓取。

## 1.3.0

- **订阅的“抓取记录”**：之前日志里没有新文章的正常检查不记录，健康订阅的日志永远是空的。现在每次抓取都会记录：时间、耗时、读到多少篇文章、新增多少篇。结果完全相同的连续检查合并成一行（例如“共 53 次检查 · 有效 36 条 · 新增 0 条”），有变化才新增一行，所以几个小时的平静只占一行。订阅详情的“日志”标签默认显示它，“运行日志”页也有“抓取记录”视图，可按有新文章、成功、失败筛选。每个订阅源保留的行数在“设置 → 订阅规则”里调整（默认 20，范围 5–200）。
- **登录需要账号和密码**：登录页新增账号栏，浏览器和 iCloud 钥匙串可以保存。首次登录账号是 `admin`（演示实例是 `preview-admin`），密码是部署时的 `WEB_PASSWORD`；账号可以在“设置 → 账户与安全”里修改（修改密码时新密码可以留空，只改账号）。不带账号的脚本请求仍然可用。
- **运行配置更紧凑**：设置按类别折叠成组，只展开第一组；每项一行，当前值和来源在左，输入控件在右；长说明收进设置名旁边的 ⓘ，点开才显示；新增搜索（设置名、变量名、说明）和“全部展开 / 全部收起”。手机上说明从底部弹出。
## 1.2.0

- **订阅多选新增三个按钮**：
  - **立即抓取**：对所选订阅涉及的订阅源逐个抓取，和定时检查一样把新文章推送给全部订阅会话；同一个源被多个会话订阅只抓一次，已暂停或不可用的订阅会被跳过。对话框里实时显示进度和每个源的结果。
  - **间隔**：一次设置所选订阅的检查间隔（或清除，改为跟随默认）。
  - **复制地址**：把所选订阅的 RSS 地址复制到剪贴板，每行一个。
- 手机上多选操作条按钮较多时会自动换行。
- API：`POST /api/subscriptions/batch` 新增 `interval` 操作；`POST /api/subscriptions/fetch-now/batch` 与 `GET /api/fetch-batches/{id}`（仅限网页管理员）。

## 1.1.2

- 修复网页“重启”偶尔卡死：进程退出时如果有线程没有结束，原本的“强制退出”在容器里（进程是 1 号进程）发出的信号会被系统忽略，于是一直停在半死状态，Docker 也不会重新拉起。现在强制退出会直接结束进程，让 `restart: unless-stopped` 把它重新拉起来；同时把所有线程的堆栈写进日志，便于查明是哪个线程没有退出。

## 1.1.1

- 修复个别网站抓取时随机失败的问题：少数派（sspai.com）等站点的部分 CDN 节点会选用强度不足的 DHE 密钥交换（`DH_KEY_TOO_SMALL`），导致握手失败，表现为“网络错误”且时好时坏。现在抓取时不再使用这类套件，改用 ECDHE / TLS 1.3，行为与浏览器一致。

## 1.1.0

- **单个订阅源的代理**：订阅详情的“抓取”标签页可以为这个源单独设置“跟随全局 / 直连 / 使用代理（http、socks4、socks5、socks5h）”，并能“测试这个设置”（只抓取一次，不推送）。服务器连不上某些网站（如海外服务器访问只部署在国内的网站）时，只需让这几个源走代理，其他订阅不受影响，也不必再设置全局 `R_PROXY`。订阅列表支持选中多条后批量设置，添加订阅时也可以填写代理。代理地址可能含密码，保存后不再显示，备份中默认不导出（需要主动勾选“订阅源的单独代理”）。
- **私聊用户的名称**：管理台上线之前就在用机器人的私聊用户，此前一直显示为“会话 N”。现在启动时会从机器人自己的 Telegram 登录会话里补全名称，会话页也新增“补全名称”按钮；仍然查不到的显示为“用户 N”。
- 机器人自己的账号不再出现在会话列表和统计里。

## 1.0.0

第一个正式版本，基于 RSS-to-Telegram-Bot 2.10。

- 全新的网页管理台：概览、会话、订阅、运行日志、设置；中英双语、浅色 / 深色、手机布局。
- 会话管理：角色、封禁、让机器人退出、推送默认值、操作记录。
- 订阅管理：筛选与批量操作、OPML、多接收会话、单源 User-Agent、最近文章与推送结果、立即抓取与测试推送。
- 运行日志直接写明失败原因。
- 通知：本机器人私聊、Telegram、Bark、ntfy、Webhook；失败、恢复、新会话。
- 运行配置可在网页修改并显示当前生效值，Telegraph Token 一键获取，网页一键重启。
- 备份与恢复、API 令牌与 OpenAPI。
- 预构建镜像 `ghcr.io/jaaayden/rsstt-web`，数据与原版兼容，可随时回退。
- 资源占用与原版基本一致。
